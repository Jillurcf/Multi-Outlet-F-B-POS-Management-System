## Status labels used across this documentation

- **Implemented** — behaviour exists in the repository today, with source references.
- **Proposed** — a design recommendation for future work; it is **not** present in the codebase.

Proposed sections are labeled explicitly. In particular, offline operation, a kitchen display system (KDS), WebSocket/SSE communication, message brokers, materialized views, caching layers and microservices are **not implemented**.

## Conventions

- Identifiers are UUIDs generated by Prisma (`@default(uuid())`) unless a deterministic UUID is supplied by the seed.
- Money is stored as integer **cents** in `INTEGER` columns; all request/response DTOs use the same `*Cents` fields.
- Timestamps are `TIMESTAMPTZ(6)` in the database and ISO-8601 strings in JSON. Report ranges are normalized to UTC day boundaries.
- Public routes are `GET /` (service identity), `GET /api/health` and `POST /api/auth/login`; all other API paths require a Bearer token.
- Successful responses return raw DTOs (no envelope); errors use `{ "error": { "code", "message", "details"? } }`.

## Verification

The repository's full verification command is:

```bash
npm run verify
```

It runs `lint`, `build`, `typecheck` and the Node test suite for the API workspace. CI executes `npm ci` followed by the same command on pushes and pull requests.
